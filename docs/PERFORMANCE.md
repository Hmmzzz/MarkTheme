# 渲染与编译性能优化

0.3.2 基于已发布的 0.3.1，仅优化性能，保持资源选择、图像效果和 Apply / Respring
流程不变。没有新增产品功能、配置字段、Hook 或目标进程。Runtime build 由 204
递增为 205，以区分进程中仍映射的旧二进制；产品版本号为 0.3.2，App build 为 27。

## 实现

- **共享解码与明确的内存上限**：同一 Generation 内复用 mask / overlay 的解码结果，
  缓存键包含资源摘要、目标像素尺寸和缩放策略。装饰图片、系统 mask 与最终图标
  共用严格的 32 MiB / 256 项 LRU 留存预算（不含调用者持有或正在合成的图像，
  不是进程峰值内存上限）。配置解析和装饰资源定位按 Generation 复用；
  已命中的最终图标仍直接返回。
- **一次图像合成**：mask 与 overlay 在同一个 RGBA context 中依次绘制，减少一个
  中间位图与一次 source 绘制。保留原有 mask 失败回原生、overlay 失败保留可用图像的处理。
- **减少无效的系统图标缓存清理**：依赖指纹涵盖 static / mask / overlay / calendar /
  clock 的模块状态、配置、资源完整 key、摘要、字节数及相关版本契约。仅修改 badge
  等非图标依赖时，可复用已完成的清理结果。首次请求仍清理；指纹计算失败时回退到完整
  Generation 标识。资源记录逐条流式哈希，最近两代结果复用。
- **清理请求串行与合并**：相邻相同依赖的请求共享一次清理，按各自 sequence 回执。
  `A → B → A` 保留最后一次清理，失败结果不进入成功缓存。Manager 原有串行应用流程
  保持不变；多个独立 Helper 并发提交时仍受既有回执超时限制。
- **编译资源计划复用**：资源一次分组，按已验证的 Manifest 摘要和组件选择缓存计划，
  最多 8 份 / 32,768 个资源引用。只保留不可变元数据，每次编译仍读取当前资产路径、
  验证文件摘要并解码 PNG，不缓存校验结果或成品 Generation。

## 已验证结果

`./tests/run`：rootless 与 roothide 各通过 **2,218 项 Foundation 断言**，两种方案输出
一致；原有 canonical digest 保持
`1d9eae74b350248accfc1693aaa77f1ca918168214093b77486fb0a181f76927`。

RootHide 与 rootless 软件包均已构建，并通过 `scripts/verify-package` 的布局、
arm64 / arm64e slices、最低系统版本、链接、entitlements、权限及进程白名单检查。
维护者已手动测试 Runtime 205 测试包，反馈未发现问题；此反馈不代表所有系统组合均已验证。

新增覆盖包括逐像素新旧合成对比、跨 App 装饰解码复用、尺寸与 Generation 隔离、
真实缓存淘汰、失败重试、真实 Kernel 连续切换、组件配置变更、资产迁移与篡改拒绝。
1,029 资源的编译用例连续执行三次，只构建一次源计划，命中两次；冷热编译结果字节一致。

宿主合成微基准（macOS 27.0.1 / 26A434，Clang `-O2`）：两种路径均预热、强制产出
像素，交替执行 7 组，每组 200 次，取每张图标耗时中位数。

## 复现

在项目根目录运行：

```bash
./tests/run
./tests/run-render-benchmarks
CLANG_MODULE_CACHE_PATH="$PWD/.work/performance/clang-module-cache" \
  ../../scripts/jb-env ./scripts/build-packages roothide rootless
```

最后一条命令只为本次构建指定项目内的 Clang 模块缓存，避免受限环境写入全局缓存；
不修改全局工具配置。构建脚本保留调试符号，并逐包执行 `scripts/verify-package`。
