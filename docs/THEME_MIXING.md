# 主题混搭与功能开关

本文档描述 MarkTheme 0.2.7 的跨主题混搭、逐功能开关和应用语义。它面向用户，也作为 Manager、Compiler
与 Runtime 之间的行为契约。

## 完整功能列表

主题详情始终展示 MarkTheme 支持的全部功能，而不是只展示当前主题已经提供资源的功能。当前支持的类别包括：

- App 静态图标与动态日历、时钟；
- 设置与分享图标；
- 文件夹、图标遮罩、overlay、角标与图标阴影；
- 状态栏资源与拨号盘。

某个主题没有对应资源时，该行仍然可见。用户可以保持系统原生外观，也可以从其他已导入主题选择资源，
因此不需要先寻找一份覆盖全部功能的基础主题。

## 来源选择

当前主题是混搭底稿。每项功能可以独立选择以下来源：

1. 当前主题；
2. 其他已导入且实际提供该功能资源的主题；
3. 系统原生外观，即关闭该功能。

来源列表只把真实拥有该功能资源的主题标为可用。删除来源主题、同主题被重新导入覆盖或能力报告更新后，
详情页会重新投影选择；失效来源不会被静默解析为另一主题。

动态日历、时钟等具有配置依赖的能力会连同其必要资源一起解析。静态图标仍按 App Bundle ID 选择最匹配的
资源，不会因为某个功能来自另一主题而扩大 Runtime 的匹配范围。

## 生效开关与系统回退

每项功能的开关控制它是否进入下一次 Generation：

- 开启：Compiler 从已选择来源解析并写入该功能；
- 关闭：Compiler 不写入该功能，Runtime 对应表面返回系统原始结果；
- 来源缺失、资源损坏或 ABI 校验失败：该功能独立回退到系统原生外观，不影响其他已验证功能。

关闭不是仅隐藏预览，也不会保留旧资源继续生效。再次应用混搭后，新的 Generation 明确移除该能力。

## Overlay 语义

图标 overlay 是独立功能，不依赖其与 App 图标来自同一主题：

- 关闭 overlay 后，新 Generation 不含 overlay 配置或资源；
- 更换 overlay 来源后，只发布新来源的 overlay；
- 没有 overlay 资源的主题不能成为该功能的有效来源；
- Runtime 缓存以当前 Generation 与资源身份为边界，主题关闭、切换或回滚时不会沿用旧 overlay。

遮罩与 overlay 同时开启时，合成顺序保持“遮罩 → overlay”。overlay 可独立覆盖普通图标和文件夹，但各自仍
必须通过尺寸、资源完整性与目标表面校验。

## 保存、预览与应用

来源和开关会按基础主题持久化。修改详情页选择不会立即改写当前 Runtime Store；用户点击底部应用按钮后，
Manager 才读取最新 Library、编译确定性 Generation，并通过固定 Helper 原子发布。

编译支持取消，且会在功能边界检查取消状态。失败不会留下半发布 Generation；当前 active 与 previous
Generation 继续承担回滚和 last-known-good 语义。应用完成后需要一次 Respring，让目标进程加载新的 Runtime
映像和 Generation 状态。

## UI 与辅助功能

- 首页主题预览提供轻量“主题详情”入口；系统默认主题没有可打开的主题实体时，该入口完全隐藏；
- 主题详情使用明确的来源选择界面，不依赖当前主题是否已有资源；
- 带关闭按钮或明确稍后操作的 Sheet 不重复显示顶部 grabber；
- 小型视觉入口仍保留至少 44 pt 的点击区域，并向辅助功能暴露独立、可操作的名称。
